# Firmware data reference

`main.py` produces two JSON files in the repo root. Both are keyed by the **firmware file name**, so join them on that
key. `docs/examples/` has real output for 23 firmwares across 10 vendors, generated by the actual pipeline.

## `cameras.json`: where each firmware came from

```json
"DH_IPC-HX1X3X-Kant_EngSpnRus_PN_V2.860.0000000.40.R.260515.zip": {
    "camera_name": ["IPC-HFW1439S1-A-IL", "IPC-HFW1230S1-A-S6", "IPC-HFW1230TC-A"],
    "changelog": "https://materialfile.dahuasecurity.com/uploads/cpq/84464/firmware/DH_Kant_Platform_Release_Notes.pdf",
    "firmware_size": 15532655,
    "firmware_version": "V2.860.0000000.40.R",
    "md5": "cb7aae9bad465cc2096f946357a88316",
    "notes": [],
    "release_date": "2026-05-29",
    "sha256": "4ec9c1a0fc936372791040e9abd7463540c703a4bf6295f73ef8a86138e35092",
    "url": "https://materialfile.dahuasecurity.com/uploads/cpq/84464/firmware/DH_IPC-HX1X3X-Kant_EngSpnRus_PN_V2.860.0000000.40.R.260515.zip",
    "vendors": ["Dahua"]
}
```

| Field | Always present | Description |
|---|---|---|
| `camera_name` | yes | Model names **as the vendors list them**: OEM SKUs (Amcrest `IP2M-841`, EmpireTech `IPC-T54IR-ZE`, Inaxsys `INS324K`) or Dahua models. Combined from every vendor that lists this file. Can be empty. |
| `notes` | yes | Free-text vendor notes, e.g. `"Only for IP2M-841 German and Italian"`, `"Product line: Diamond/PTZ"`, `"Compatible models: NR32P4-4C"`. RVI notes are in Russian. Often empty. |
| `url` | yes | Download URL from the most recent listing. May be a plain file, a MEGA link (EmpireTech), a Google Drive download link (ENS), a SharePoint link (Inaxsys) or a redirect API (RVI), so treat it as "where to get it", not as a file name. Links can die; `url` is the last place it was seen. |
| `vendors` | yes* | Vendors that list this file, e.g. `["Dahua", "EmpireTech"]`. Values: `Amcrest`, `Dahua`, `EmpireTech`, `ENS Security`, `GSS`, `Inaxsys`, `Lorex`, `Montavue`, `Optiview`, `Rhino`, `RVI`, `Speco`, `VIP Vision`. *Entries no vendor has listed since vendor tracking was added have no `vendors` yet. |
| `firmware_size` | once downloaded | Size in bytes of the downloaded file. |
| `platform` | once downloaded | `dahua`, `hikvision` or `unknown`, identified from the file's header (looking inside zips) and Dahua's file naming. **Not every vendor here only sells Dahua**: GSS Red\|LINE is Hikvision, and some Lorex, FLIR and old Amcrest analog DVRs are other platforms (`unknown`). Filter on this before treating a firmware as Dahua-compatible. |
| `firmware_version` | optional | Version without the build date, the way a Dahua device shows it (`V2.860.0000000.40.R`). Some vendors (GSS, Montavue) have no Dahua-style version, so this is the vendor's own label (`K74_V3.4.98_180104-1`). |
| `release_date` | optional | `YYYY-MM-DD`. The vendor's listed date when there is one (Dahua's posting date, Amcrest's table date), otherwise the build date from the version string. |
| `changelog` | optional | URL to release notes (PDF/TXT). |
| `md5`, `sha256` | optional | Checksums published by the vendor (Dahua Download Center only). Downloads are verified against `md5`. |
| `listings` | once listed | **What each vendor page says, kept separately.** One object per vendor page (see below). Use this to say "EmpireTech sells this as IPC-T54IR-ZE" or to offer every vendor's download link. Firmwares that no vendor lists anymore get one inferred from their download host, with a `source` like `dahuawiki.com (found in an earlier scrape)`. |
| `archive_item` | once archived | Internet Archive item page for this firmware, e.g. `https://archive.org/details/cctv-firmware-...`. |
| `archive_url` | once archived | **Permanent direct download** from the Internet Archive. Prefer this over `url`, since vendor links break. For firmwares no vendor hosts any more, it's the only working link. |

The top-level `camera_name`, `notes`, `url`, `firmware_version`, `release_date` and `changelog` combine all vendors
(the `url`, version and date come from whichever listing was processed most recently). `listings` has the per-vendor
detail:

```json
"listings": [
    {
        "vendor": "EmpireTech",
        "source": "EmpireTech",
        "camera_name": ["NVR5208-8P-4KS2E", "NVR5216-16P-4KS2E"],
        "notes": [],
        "url": "https://mega.nz/folder/...",
        "firmware_version": "V4.002.0000000.8.R",
        "release_date": "2024-11-02"
    },
    {
        "vendor": "Inaxsys",
        "source": "Inaxsys STORM",
        "camera_name": ["INS8824KN"],
        "notes": ["STORM NVR"],
        "url": "https://inaxsys.sharepoint.com/...?download=1",
        "firmware_version": "V4.002.0000000.8.R",
        "release_date": "2024-10-30"
    }
]
```

| Listing field | Description |
|---|---|
| `vendor` | Vendor name, same values as `vendors`. |
| `source` | Which page or module of that vendor listed it, e.g. `Dahua Download Center` vs `DahuaFileDirectory` (dahuawiki), or `GSS - Blue\|LINE NVR`. A vendor can have several listings from different sources. |
| `camera_name`, `notes`, `url` | That vendor's own model names, notes and download link. |
| `firmware_version`, `release_date`, `changelog` | That vendor's details, when given. |

## Internet Archive

Every downloaded firmware is uploaded to its own Internet Archive item (`python main.py archive` runs just that
step). All items are tagged `amcrest-compatible-finder`, so the whole archive is listed at
https://archive.org/search?query=subject%3A%22amcrest-compatible-finder%22. Each item's description repeats the
vendors, model names, hardware IDs, version, checksums and original URL.

## `firmware_compatible.json`: what hardware each firmware supports

```json
"DH_IPC-HX1X3X-Kant_EngSpnRus_PN_V2.860.0000000.40.R.260515.zip": [
    "IPC-B1E29-A-IL-S2", "IPC-HFW1230B-A-IL", "IPC-HFW1230S1-A-S6", "IPC-HFW1439S1P-IL", "..."
]
```

A sorted list of **hardware IDs read from inside the firmware**: the board/model IDs the firmware's installer accepts
(from `check.img` hwids, `Install`/`Install.lua`, or the u-boot image name). This is what the firmware will install
on, and it's usually much longer than the vendor's `camera_name` list.

- **This is the cross-vendor link.** Two firmwares from different vendors that share hardware IDs run on the same
  hardware. For example, an Amcrest SKU can be matched to the Dahua or EmpireTech firmware for the same board.
- IDs come in different forms: Dahua models (`IPC-HFW1230S1-A-S6`), board families (`NVR4X-4KS2/L`, `HCVR5x04-S2`),
  and for some older IPCs raw 16-character hex hardware IDs (`0800425346118427`). A good site shows all of them and
  makes the readable ones searchable.
- Some entries also contain vendor tokens from installer scripts, such as `DAHUA` or `Group` (RVI). Ignore or
  down-weight them; they aren't models.
- `[]` means it was processed but no IDs were found (an unrecognised layout, or not Dahua firmware at all, e.g. GSS
  Red|LINE `.dav` files, which are Hikvision). These are retried on later runs.
- A key that's in `cameras.json` but missing here hasn't been downloaded or processed yet.

## Suggested site model

1. **Firmware pages**: one per key, combining both files. Show each vendor's listing (their model names, notes and
   link), the version, release date, changelog, size and checksums, the hardware ID list, and the Internet Archive
   download (`archive_url`) as the primary link.
2. **Hardware ID pages**: invert `firmware_compatible.json` to get `hardware ID -> [firmware files]`, sorted by
   `release_date` (newest first) so the latest compatible firmware from any vendor is at the top.
3. **Model search**: index both `camera_name` (vendor SKUs) and the hardware IDs, so searching for an OEM SKU leads
   to its firmware and then to every other firmware for the same hardware.
